# 按具体问题重写的轻量 CI 规范

生效：2026-10-23。所有者本次明确要求：**每次根据具体问题重写测试流文件**。
本规范更新旧的固定全量选测约定；各仓库现有科学判据、权限边界、唯一 Runner 限制及分支保护继续有效。

## 每次任务必须落实到工作流文件

1. 先读当前 main、实际差异、调用方、共享接口和失败日志，写清本次要解决的问题、影响范围和验收条件。
2. 每次根据该问题重写或更新对应 `.github/workflows/*.yml` 的测试任务、具体命令、输入 SHA、触发条件、超时与结果摘要。仅改一份计划、沿用旧全量工作流或在聊天中说“针对性测试”不算完成。
3. 优先改写已有普通入口中的本次测试流，删除已失效的临时诊断步骤，不为每个问题长期叠加一套重复入口。稳定的权限、来源校验及结果协议可保留复用。
4. 重写前列出“问题 → 不变量/契约 → 具体测试 → 通过标准”；对删减的旧测试说明不相关的依据。涉及共享代码时覆盖必要下游，不能只依据文件后缀跳过。
5. 不具备自动 CI 的文档/资源仓库，本次使用本地文档检查；后续确需自动执行时才建立问题对应的工作流。统一规范分发本身不强制给这些仓库安装 Runner。

## 最小充分验证

| 变更 | 默认执行 | 扩大范围条件 |
| --- | --- | --- |
| 文档、治理、网络状态记录 | 引用、事实、脱敏、`git diff --check` | 可执行示例或配置行为改变 |
| CI/脚本 | YAML/表达式和脚本语法、事件/身份/失败分支回归、一次最小真实执行 | 公共调度或构建链受影响 |
| 网络/入口 | DNS/TLS/HTTP、登录与拒绝路径、上游健康、普通/大文件通道 | 改变鉴权、路由、压缩或缓存时增加相应真实验证 |
| API/界面 | 受影响契约、正常/错误/边界和必要浏览器路径 | 共享状态、协议、数据格式影响下游 |
| 数值/求解器 | 相关具名单测、独立解析/参考、守恒与失败条件 | 共享物性、网格或并行接口影响相关模型/规模 |
| MPI/网格/性能 | 代表性真实输入、必要 rank/规模及资源数据 | 明确发布基线或仅大规模暴露的问题 |

默认禁止无理由重复全仓库、全模型、全 MPI、全部历史诊断；不得降低容差、改参考值或忽略失败来获得绿灯。
文档轻量检查建议 2–5 分钟，针对性 smoke 5–15 分钟；长科学任务依据实测另设预算，并记录输入、停止条件、峰值资源和未覆盖项。

## 触发、身份、资源与失败处理

- 一个有效提交批次只进入一个普通验证入口。任务开始前固定 source SHA；PR 验证明确 tested SHA 是 PR HEAD 还是 merge SHA，不能混用历史绿灯。
- PR 自托管任务必须核验所有者/允许的操作者、同仓库、目标分支和当前 SHA；fork 代码不得借高权限控制入口执行。普通检查默认 `contents: read`，checkout 不保留凭据。
- Required check 应始终给出汇总状态；不能因路径筛选使其永久等待。无相关测试时明确标注范围与未执行，不能伪称科学测试通过。
- 普通无副作用验证可按 PR/ref 取消过时任务；部署、主机控制和持久实验串行，不能盲目取消。共享同一物理主机的多个 Runner 仍共享 CPU/内存/网络，重型任务须控制实际并发。
- 先区分 queued、in_progress、completed；在线不等于任务成功。失败后先读实际失败步骤，区分 DNS/TLS/checkout、依赖、编译、数值断言和证据导出故障。
- 不自动重跑直到变绿、不自动换机器/层级；修复确定原因后只重跑受影响检查，记录前后 run/attempt/SHA。网络暂态也保留原始失败，不以最后一次成功抹去抖动。
- 缓存仅为优化，缓存键绑定工具链与依赖锁；禁用缓存的仓库继续禁用。不得把旧构建产物当本次源码验证。各仓库原有证据存储规则继续有效，规范分发不启用新的 Artifact 上传。
- 日志和 Step Summary 记录问题、范围、实际命令、SHA、Runner、结果与缺口；不输出密码、Cookie、Token、会话库或业务正文。原始日志留在私有工作目录，长期文档只记有依据的结论。

## 本次应用与完成标准

本次问题是网络状态缺乏可重复巡检及主机控制恢复分支错误。`ubuntu26` 的测试流为只读双入口巡检、主机请求解析/条件回归；其他仓库仅接收规范和适用的网络摘要，按文档范围验证。

完成须同时满足：工作流与本次问题一致；选定检查真实执行；失败/未测诚实记录；提交进入目标主分支；回读远端 SHA 与文件。受保护主分支采用其允许的合并流程，不绕过保护。
