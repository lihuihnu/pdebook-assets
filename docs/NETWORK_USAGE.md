# 网络连接与排错使用方法

更新：2026-10-23。本文仅描述通用方法，不保存私有项目的主机、地址、端口、账号、VPN 或拓扑。

- GitHub 使用当前已授权的 CLI：`gh api user --jq .login` 检查身份，`gh run list --repo OWNER/REPO --limit 5` 查任务，`gh run view RUN_ID --repo OWNER/REPO --log-failed` 查失败步骤。先区分网络、认证、排队和测试失败；写操作结果不明时核对远端，禁止盲目重发。
- 代理使用按目标分流：统一大小写 proxy/no_proxy，保留 TLS 与凭据保护；经对照验证确有问题的路径才调整。私有运维主机的专用工具、部署与回滚方法保存在其私有运维仓库，不能在普通机器假定存在。
- 网站使用维护者提供的主入口；备用入口可能退化。此次实测主入口采用按目标直连后明显改善，但不构成持续速度承诺，也不证明登录后的业务或大文件验收。
- 如某个独立科研任务需要超算，遵循站点授权的 VPN/SSH 方法；断线后先查询已有调度任务，不盲目重新提交。此说明不为本项目引入超算、网站或运行时网络依赖。
- 每次根据具体问题重写测试流文件，采用小范围、明确超时、真实结果的验证，并遵守本仓库既有 Runner、隐私和发布约束。
